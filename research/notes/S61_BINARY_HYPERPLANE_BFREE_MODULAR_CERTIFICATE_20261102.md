# B-free 多項式行列の指定点全射と次数を保つ小行列

2026-11-02。

## 1. 証明する内容

入力は B-free 模型の三次式の一次倍などから得る321×238行列
\(M(a,e,d)\) と七つの標的行である。本証明書は入力生成を独立には
実施せず、外側の元135式 producer が生成した同じ行列を受け取る。
各 entry は QQ[a,e,d] の疎多項式として与える。

p=32003, (a,e)=(1,2) において、次を直接検証する。

1. 元321行のうち指定238行を取り、元の列順のまま作る行列式は
   d 次数259、最高次係数6872である。
2. 全321行が生成する Fp[d] 行加群は Fp[d]^238 全体である。
3. 入力の全有理係数は p 整で、七標的を含む全328×238 entry の
   指定点への特殊化が与えられた Fp[d] 入力と一致する。
4. 保存された全行・全列の重みについて
   \(\deg_d M_{ij}\le r_i+c_j\) を元 QQ 多項式の指数から再検査する。

この証明書だけで全 core 上の全射や周囲環の飽和除去は結論しない。

## 2. 元の行の選択と次数比較

固定された238行の番号は
`code/certificates/s61_binary_hyperplane_Bfree_minor_selection_20261102.json`
に保存する。旧有限体 Schur 計算の pivot origin から選んだが、旧計算は
provenance に限る。今回の証明は選択した元多項式行列の行列式を改めて
`nmod_poly_mat_det_interpolate` で計算する。
さらに d=0,3,17 で元行列の数値行列式と返された多項式を照合する。

選択行の重み和は -128、全列の重み和は512であり、合計は384。
\(\delta=1/d\) として

\[
\widetilde M_{ij}(\delta)=\delta^{r_i+c_j}M_{ij}(1/\delta)
\]

は非負次数の多項式である。別証明で、全238次小行列の正規化δ付値が
125以上と示された場合、今回選択した行列式 P について

\[
\deg_d P\le384-125=259
\]

が従う。指定有限体点で実際に次数259・最高次係数6872を持つため、この
条件付き上界は鋭く、Pの259次係数は
\(V=\mathbb Z_{(p)}[a,e]_{(p,a-1,e-2)}\) の単元となる。
QQ上のδ付値125の下界は本 helper の検証範囲外であり、外側の
厳密 Schur-kernel 証明と結合する条件として明記する。

## 3. 多項式行加群の全射

native は全321行を順に処理する。各非零行の最大次数、同次数なら最大
列番号を leading position とする。同じ leading position の二行に
対して、Fp の非零定数で割り、多項式の単項式倍を引く。
必要な交換を含め、処理中の全行が生成する Fp[d] 加群を保存する。
非定数多項式での行除算は一切しない。

最後には238本すべての基底行の次数が零となり、相異なる leading
position を持つ。定数基底行列は三角で対角成分がすべて非零である。
さらにこの定数行列の行列式も独立に計算して非零を検証する。
したがって元321行の加群は Fp[d]^238 である。

前節の QQ 次数上界と元行列の V 上の正則性が別途得られれば、P を
最高次係数で割って monic にできるため coker M は有限 V 加群となる。
本節で特殊ファイバーが零なので Nakayama により coker M=0 となる。
この結合は外側の定理が担当し、helper 単独では QQ δ付値や元135式からの
生成過程を仮定なしに主張しない。

## 4. 再利用 API

```
from s61_binary_hyperplane_Bfree_modular_certificate_20261102 import run_minor_module
certificate = run_minor_module(wd, core_matrix, univariate)
```

core_matrix の形式は先頭 `328 238 321`、以後 entry ごとに一行で
`項数 (有理係数 a指数 e指数 d指数)*` である。
univariate は先頭 `32003 321 238 7`、次に旧Bの二係数（本検証では未使用）、
以後行ごとに非零列数、各列の番号・係数数・昇順係数を記録する。

実行ファイルと native 出力は /tmp 内で生成し、Python が wd へログと
小証明書をコピーする。CLI の出力先は必須で上書きしない。
正式 source、固定選択、note の hash と、外側が与えた fresh 二入力の
hash を区別して保存する。巨大な旧 work cache は正式依存に含めない。
