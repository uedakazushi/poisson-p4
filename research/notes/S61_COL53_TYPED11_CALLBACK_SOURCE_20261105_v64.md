# 型付き第11段の全 callback・RHS（SOURCE のみ）

独立確認済みの full F11 非零証明を用い、現行 full167×14 から full166×13 への一段の Schur callback を有限の型付き演算として記録する。F11 は1203ノードの元の全有限式であり、411項の H=-3 面ではない。追加 chart は旧 chart 内の D(F11) で、F9/F10 と全旧・新補集合を残す。

現行共通表現 D10=U²F9F10、N10=D10*M10、および Np=P7F9F11 に対し、

    p=Np/D10,
    N11(i,j)=Np*N10(i,j)-N10(i,53)*N10(6,j),
    D11=D10*Np,
    lambda(i)=N10(i,53)/Np

を用いる。Np や F11 を展開せず、現行 manifest で所有者を固定した N10 callback を参照する。新しい係数値は計算しない。余分な約分・GCD・因数の仮定を置かない。

全166×13の根、全166 RHS、全 lambda と、pivot 行の残り13個の元 callback を明示する。66本の制約係数行が零であることから新しいその係数行も零であるが、対応するRHSは元のRHSのまま保持し、零と置かない。87本の追加RHSも同じ演算で運ぶ。逆代入は (D10*h10(6)-sum N10(6,j)*xj)/Np であり、以前の69段の復元とP290一回を保つ。選択13×13だけを full cokernel と同一視しない。

準備ワーカーは SOURCE 型データのみを構築し、型付きノード・全索引・文書・出力の所有量とRAWを事前課金する。既存の F9/F10 保存係数から正のL1上界を取り、full F11 の正の SOURCE majorant を使って Np と D11 の正上界を記録する。新しい N11 の支持数・L1上界には旧 callback の正上界を引数とする厳密な式を示すが、まだ全旧 callback の数値を代入した VALUE 予算ではない。どの新しい係数 VALUE に進む場合も、別の数値化済みSOURCE・実装・所有量・RAWゲートが必要である。

全体逆行列・全係数応答・exhaustion は未解決である。本 packet は形式 callback の構成と保存だけであり、新しい行列・RHSの係数更新を実行したという意味ではない。
