# 四つの残余三次係数の既存キャッシュ読出しの独立 SOURCE 監査

条件付き一回の読出しに先立ち、元の演算、同一フレーム、厳密な分数処理、寿命管理、停止条件を独立に確認した。要求された八つの根の正次数係数および四つの α の値は、この監査では計算していない。

元の 18,584 演算の受理済みスナップショットと照合して、固定された八根に必要な 7,945 演算が文字通り同じであり、祖先集合を過不足なく含むことを確認した。原始入力は同じ 105 個で、実際の方程式 ID と r,s の固定座標も同じである。既存の105入力の下位630係数を Q20 と再照合し、固定 Jacobian の非零有理数による同一フレームの証明を結び付けた。s=r+ell/5 と B6=(r²,ell³) への射影は環準同型であり、単位逆数とも可換である。

四つの α は物理行 19,28,29,72 の実際の aA−aB の r ell² 係数である。受理済み完全155源の証明へ、八つの even 根と全四源ラベルを結び付けた。入力の係数抽出式 `(δ_(r*s²)+3δ_(s³))/25` だけを記号的に確認し、δ の対合は行っていない。旧 C2 と pure-ell の独立受理済みデータによって、八根の下位40値と四差の下位零条件を確認した。

45 個の有理定数は分子・分母の両方を使用し、うち32個は非整数である。作者の評価器を使わず、正次数については絶対値上界と分母の割り切り上界だけを再構成した。全ノードのメタデータハッシュ、39 bit の保存係数上界、最大184ノードの last-use 寿命が一致した。独立の演算前上界は元 DAG 61、入力変換40、逆数検算35、最後の差22 bit であり、公表された全段階79 bit、厳密上限2048 bit の範囲内である。

実行予定コードの構文を確認し、分数の和・積・構築の前のガード、二方向の逆数積、630入力照合、40旧根照合、根だけの停止保存を確認した。既存入力と出力予約を含む全 59,866 セルは静的70,000、親の75,000、絶対100,000の枠内である。SOURCE の独立監査は125,000以内、絶対150,000で行った。60秒、2GB、32MiBの枠を変更しない。

独立監査側の途中失敗は保存した。二つの汎用 JSON セレクタは minified JSON の入れ子キーを誤認したため、深さを追うトップレベル選択へ修正した。また零係数の分母上界を1へ正規化したためのハッシュ差、リスト反復を係数積と誤認した構文検査、bool 制御セル20個の計数規約差を修正した。いずれも作者のデータやコードは変更せず、根の値を計算する前の監査上の問題であった。

この PASS は同じ一回の既存キャッシュ読出しの条件を満たす。α が非零なら完全な追加三次階数1、HF3=3、長さ上界19。全零なら追加階数0、HF3=4、長さ下界19となるが、いずれも C3 全長や全ねじれ指数を単独では決めない。

再現用コードは `ambient_B18_C3_alpha4_cached_source_review_20261105_v63.py` と `ambient_B18_C3_alpha4_cached_source_finish_review_20261105_v63.py`。終了済み境界計算は固定チェックポイントから読み込み、再評価しない。既存レポートや出力先は上書きしない。
