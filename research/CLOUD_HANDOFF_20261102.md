## 作業台の回収と未完の判定

* **非平方、\(a=0\)**。[中央環の入力・検算ログ](handoff/20261102/binary_a_zero/) と `code/s61_binary_a_zero_{atlas,ray_transverse,row_determinant}_20261102.*`、七つの有理代表点の [係数表](../code/certificates/s61_binary_a_zero_points_20261102.json) を収録。\(K=5c+f=0,c=d=1,e=8b/3+7\) の試験直線で、\(\mathbf F_{32003}[b]\) 上の重み4の行加群は531行386列、行列式の次数17。例外の \(e/b\) は \(2,5/3,5/4,-10,5/2,25/14,5\)。重み3の追加条件の零点もこの集合に入る。六値の非零方向の横断長は順に2、2、3、1と1、23、2。第七値の中心長は70。試験用 \(d=0\) 標本は長65。古いタイムアウトと後続の成功ログを両方収録した。これらは点別の計算である。**全 \(a=0\) 層の除去は未証明**。次に正標数の代表点ごとの入射の平坦な持上げ、周囲での実加群の消滅、試験直線上の固有性による標数零への移行を確認する。
* **非平方、\(d=0\)**。[担当者の証拠・手順](handoff/20261102/generic_fiber/README.md)。固定した支持面の試験直線で有限部の561行269列の全射と、無限遠の旗での中心長76・飽和後31を有限体上で確認。混合標数の旗の近傍での平坦性・消滅が未証明。
* **平方、\(c=2a\)**。[係数、完全な行列、途中計算](handoff/20261102/mps_catalog/README.md)。重み5の2022行932列で有限体上の候補は \(h+3083\)、\(h+28920\) の二因子。これは探索値。一般 Buchberger 計算と \(\mathbb Q(h)\) 上の行簡約は中断済み。次は小さい重み6の積を扱う。有限体の例外を標数零の因子と同一視しない。
* **固定二座標の有限候補**。[モデル、元入力、再現手順](handoff/20261102/elliptic_jets/README.md)。未飽和の無限遠で22曲線を記述する `S61_FIXED_PAIR_INFINITY_CURVES_20261102` はコード・ノート・報告とも保存したが、最終独立確認前の原稿。主張台帳への採録は保留。一般三切断の長さ2300からアフィン次数は推定できない。

## Cloud で開いた直後の操作

まず対象ブランチと保存物を軽く確認する。以下はすべてリポジトリ直下で実行する。

```sh
git rev-parse HEAD
git log -1 --oneline -- research/CLOUD_HANDOFF_20261102.md
sha256sum -c research/handoff/20261102/SHA256SUMS
bash scripts/setup.sh
```

セットアップが、固定した Python 依存を導入し、同梱の `sources/v02.zip` ～ `v24.zip` から `legacy/` を復元する。Python 3.11以上、ローカル実績は3.14.10、SymPy 1.14.0・NumPy 2.3.5・mpmath 1.3.0。ネイティブ部分には C++17、FLINT 3.x（実績3.5.0）、GMP、MPFR と Macaulay2（実績1.26.05）が要る。Linux では `pkg-config --cflags --libs flint` と `command -v M2` を確認し、古い scratch の Homebrew 絶対パス・dylib 設定を Cloud の実体に合わせる。証明書にハッシュ記録のあるソースは、移植用コピーと区別する。今回 Cloud 環境上の実行はしていない。

最初の数学作業は \(a=0\) の七代表の既存記録を読んで、上表の点別計算から必要な混合標数の補題を切り出すこと。保存時の作業台を復元して、小さい二つの照合から始められる。

```sh
tar -xzf research/handoff/20261102/binary_a_zero/binary_a_zero_wip.tar.gz work
cat work/h11-a0-coverage2.log work/h11-a0-mixed-rays.log
.venv/bin/python work/h11-h3.py
.venv/bin/python work/h11-run-rays.py
```

元の行列式だけを再現する場合は、保存済み入力を直接使える。次の出力先は新しい作業ファイルにする。

```sh
tar -xzf research/handoff/20261102/binary_a_zero/binary_a_zero_wip.tar.gz tmp/h11-a0-full-weight4.in
c++ -std=c++17 -O3 code/s61_binary_a_zero_row_determinant_20261102.cpp \
  $(pkg-config --cflags --libs flint) -o work/a-zero-det
work/a-zero-det tmp/h11-a0-full-weight4.in > work/a-zero-det-cloud.txt
```

## 保存範囲と停止状態

`work/`、`/tmp/`、システム一時領域、未追跡ファイルを確認した。`reports/tmp/` は停止時に存在しない。上の四作業台に加え、[統合作業の履歴](handoff/20261102/integration/) に未完成の v60 版スクリプト・台帳照合記録・v59 配布照合記録、旧草稿、過去の2回の integrity 実行ログを保存した。古い不合格ログはその後の合格ログと区別してある。統合スクリプトは台帳への追加を済ませた状態の記録であり、そのまま二度適用しない。v60 原稿・PDF を作成する前にページ数等は実測し、旧スクリプト中の v59 用定数を引き継がない。

[過去の二平面型の試行](handoff/20261102/prior_binary_probes/) には、手元で既に研究用に選別されていた37個のアーカイブのデータ・ソース・ログを重複排除して収録した。旧実行ファイルはソースから再構築できる。新しい数学的証拠としての採録はしていない。仮想環境、Homebrew ランタイム、ビルドキャッシュ、旧配布用 clone・重複 ZIP、改行一文字だけの `PASS` は引継ぎ入力に含めない。既存のローカルファイルはそのまま保持した。

3人の子エージェントは保存作業を終えて終了。親が直前に起動した6つの計算セッションも終了コードを回収した。失敗した旧試行の入出力と後続結果は上記アーカイブにある。作業ディレクトリの開いたプロセスと各担当のセッションも照合した。ローカルで研究を継続する常駐ジョブはない。Cloud の再開に必要な研究データの保存不能項目はない。
