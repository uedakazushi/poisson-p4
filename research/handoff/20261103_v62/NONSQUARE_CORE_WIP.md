# 非平方 core の v62 探索入力と未完成計算

三つの完了補題（六二次式の全点階数6、積対の全点座標被覆、H11共通枠欠落のproper β像）は、通常の code/report/note に保存した。この tar はその後に試した未完成の三次・飽和計算を保存する。研究停止指示ではない。

## heavy 三次 block

`heavy.py` は既存の exact template と定数行変換から15×7行列を構成し、指定 aFBC 単元だけを払い除く。全 core の row-module Gröbner 計算は QQ で120秒、Fp(a)[e,d] で90秒まで実行して未完。これらは全体の階数被覆を与えない。

一方、a=1 の F32003[e,d,(FBC)^-1] 上では row-module 計算が完了した。rank7欠損の cokernel の台は長さ4の零次元スキームである。保存した module GB を独立した小入力へ戻して annihilator と lex GB を計算すると、z の eliminant は

    z^4−2668z^3+15538z²+4578z+4518
    =(z²+235z+1065)(z²−2903z−7388)  mod 32003.

二つの二次因子は既約。e,d は `heavy-a1-lex.log` の z 三次式で表される。この台があるため、heavy block が全点で rank7 だという目標は正しくない。

`fieldrank.py` は二つの二次数体上で、旧候補アーカイブの42×70全三次Schur行列を評価し、両方とも階数36を得た。heavy欠損の四点でも pure cubic が不足を補っていることを示す探索的観察である。ここで使った旧入力のハッシュは現在の cubic producer の pinned hash と一致しないため、この行列を新しい定理の証拠に採録していない。元135式から現行行列を再構成して一致を確認する段階が残る。

`heavy64.py` は32個の7行選択を有限体の非零評価で選び、既存の exact QQ native determinant に渡す。全32小行列式の計算は6.01秒で完了した。行列式を既知単元で割った32多項式に対する Fp の全 core GB は90秒で未完である。gcd が単元という既知結果以上の支持次元を主張しない。入力と exact native は保存済み source から再生成できる。

## 中央 t≠0 を直接計算する試行

`partial-affine.py` は11月2日の a-only10変数部分模型（134式のみ、G6なし）を取り、a=1 とし、追跡された `a^9*t` の分子を1に固定する。dFBC も逆にする。61式、10法線＋e,d,z の入力は元候補 JSON から再生成できる。通常 GB は90秒で未完。

同じ数学入力で算法を `groebnerBasis(...,Strategy=>"F4")` へ変更した試行は、2GBの仮想メモリ上限で `std::bad_alloc` となった。この失敗を空 ideal や t 冪零性として報告しない。現行 full135 の確定模型へ移すには、省略されている G6 を元の33置換へ通して追加する必要もある。

## 一般点での完全交叉と使えない切断

二次積対の残る四式を ℓ=0 上で見ると、(a,e,d)=(1,2,3) では完全交叉(2,2,2,2)、Hilbert級数 `(1+T)^4/(1−T)^2` となる。しかしさらに Z=W=0 で切ると次元1・次数4が残る。従って、この固定二切断の有限性で全 cubic-product rank を証明する経路は使えない。
